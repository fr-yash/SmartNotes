================================================================================
                        SMARTNOTES - PROJECT SUMMARY
================================================================================

PROJECT NAME: SmartNotes
DESCRIPTION: A full-stack web application for creating, managing, and sharing 
             notes with AI-powered features for summarization, analysis, and 
             interactive learning.

TECH STACK:
- Frontend: React (Vite), Tailwind CSS, React Router
- Backend: Node.js, Express.js
- Database: MongoDB
- AI Integration: Google Gemini API
- Authentication: JWT (JSON Web Tokens)
- File Upload: PDF support with file handling

================================================================================
                            CORE FUNCTIONALITIES
================================================================================

1. USER AUTHENTICATION & AUTHORIZATION
   - User Registration (Signup)
   - User Login with JWT token generation
   - Role-based access control (User, Admin)
   - Password hashing and security
   - Token-based authentication for all protected routes
   - Account suspension and appeal system

2. NOTE MANAGEMENT
   - Create notes with title and content
   - Read/View all user's notes
   - Update/Edit existing notes
   - Delete notes
   - Share notes with other users
   - View shared notes from other users
   - Note timestamps (created, updated)

3. AI-POWERED FEATURES
   - Summarize Notes: Generate comprehensive summaries with 4 structured tasks
     * Detailed Summary
     * Teacher Explanation (simple language)
     * Study Notes Format (bullet points, keywords)
     * Possible Exam Questions (5-10 questions)
   - Extract Keywords: Identify key terms from notes
   - Rewrite Content: Rephrase notes in different styles
   - Ask AI: Interactive Q&A about note content
   - Generate Quiz: Create 5 MCQ questions with explanations
   - AI Request Rate Limiting: 100 requests per user per day

4. PDF MANAGEMENT
   - Upload PDF files
   - Extract text from PDFs
   - Process PDF content with AI features
   - Store PDF metadata

5. ADMIN DASHBOARD
   - View all users in the system
   - View analytics (total users, notes, AI requests)
   - Suspend/Unsuspend user accounts
   - Promote users to admin role
   - Demote admins to user role
   - Manage suspension appeals
   - Approve/Reject user appeals with custom responses

6. USER SUSPENSION & APPEAL SYSTEM
   - Admin can suspend user accounts
   - Suspended users cannot login normally
   - Suspended users can submit appeals with reasons
   - Appeal history tracking
   - Admin review and approval/rejection of appeals
   - Automatic user reactivation on appeal approval
   - Admin response messages for appeals

7. EXPORT FUNCTIONALITY
   - Export notes to multiple formats (PDF, Word, Text)
   - Batch export capabilities

================================================================================
                            DATA MODELS
================================================================================

USER MODEL:
- _id: ObjectId (unique identifier)
- name: String (required)
- email: String (required, unique, lowercase)
- password: String (required, hashed)
- role: String (enum: 'user', 'admin', default: 'user')
- isActive: Boolean (default: true, for suspension)
- aiRequestsToday: Number (default: 0, for rate limiting)
- aiRequestsLimit: Number (default: 100)
- lastAIRequestReset: Date (for daily reset)
- timestamps: createdAt, updatedAt

NOTE MODEL:
- _id: ObjectId (unique identifier)
- title: String (required)
- content: String (required)
- summary: String (optional, AI-generated)
- user: ObjectId (reference to User, required)
- sharedWith: Array of ObjectIds (references to Users)
- timestamps: createdAt, updatedAt

SUSPENSION REQUEST MODEL:
- _id: ObjectId (unique identifier)
- user: ObjectId (reference to User, required)
- userEmail: String (required)
- userName: String (required)
- reason: String (required, min 10 characters)
- status: String (enum: 'pending', 'approved', 'rejected', default: 'pending')
- adminResponse: String (optional, admin's response message)
- resolvedAt: Date (when appeal was resolved)
- resolvedBy: ObjectId (reference to Admin User)
- timestamps: createdAt, updatedAt

================================================================================
                            API ENDPOINTS
================================================================================

AUTHENTICATION ROUTES (/api/auth):
- POST /signup - Register new user
- POST /login - Login user (returns JWT token)

NOTE ROUTES (/api/notes):
- POST / - Create new note
- GET / - Get all user's notes (owned + shared)
- GET /:id - Get specific note
- PATCH /:id - Update note
- DELETE /:id - Delete note
- POST /:id/share - Share note with user
- DELETE /:id/unshare - Unshare note

AI ROUTES (/api/ai):
- POST /summarize - Summarize note content
- POST /keywords - Extract keywords
- POST /rewrite - Rewrite content
- POST /ask - Ask AI about content
- POST /quiz - Generate quiz questions

PDF ROUTES (/api/pdf):
- POST /upload - Upload PDF file
- GET /:id - Get PDF details

ADMIN ROUTES (/api/admin):
- GET /analytics - Get system analytics
- GET /users - Get all users
- PATCH /users/:id/suspend - Suspend user
- PATCH /users/:id/unsuspend - Unsuspend user
- PATCH /users/:id/promote - Promote to admin
- PATCH /users/:id/demote - Demote to user

SUSPENSION REQUEST ROUTES (/api/suspension-requests):
- POST /submit - Submit appeal (suspended user)
- GET /my-requests - Get user's appeals
- GET / - Get all appeals (admin only)
- PATCH /:requestId/approve - Approve appeal (admin)
- PATCH /:requestId/reject - Reject appeal (admin)

================================================================================
                            WORKFLOW EXAMPLES
================================================================================

WORKFLOW 1: Create and Summarize a Note
1. User logs in
2. User creates note with title and content
3. User clicks "Summarize" button
4. AI generates 4-part summary (detailed, teacher explanation, study notes, questions)
5. User views results in modal
6. User can export or save summary

WORKFLOW 2: Share Note with Another User
1. User creates note
2. User clicks "Share" button
3. User enters recipient's email
4. Note appears in recipient's dashboard
5. Recipient can view but not edit shared note

WORKFLOW 3: Admin Suspends User
1. Admin goes to Admin Dashboard → Users tab
2. Admin finds user and clicks "Suspend"
3. User's isActive set to false
4. User cannot login (gets 403 error)
5. User is redirected to appeal page

WORKFLOW 4: Suspended User Appeals
1. Suspended user tries to login
2. Gets 403 error with token
3. Redirected to /suspended page
4. User submits appeal with reason
5. Appeal stored in database
6. Admin sees appeal in Appeals tab
7. Admin approves/rejects with response
8. User reactivated on approval
9. User can login again

WORKFLOW 5: Admin Reviews Analytics
1. Admin logs in
2. Goes to Admin Dashboard → Analytics tab
3. Views total users, notes, AI requests
4. Can see system usage statistics
